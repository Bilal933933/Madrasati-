## 1. الفلسفة الأساسية

### 1.1 الدرس محرك، لا صفحة

- الطالب لا يرى صفحة طويلة فيها عناصر، بل **يعيش رحلة**.
- نتعامل مع الدرس بصفته **State Machine** (آلة حالات)، لا مستند HTML.
- كل مرحلة (Stage) كائن له: **دخول — تنفيذ — خروج — شرط انتقال**.
- الواجهة (React) مجرد **عرض**؛ المراحل تأتي من المحرك، والمكونات لا تحوي أي منطق انتقالي.

### 1.2 الدرس مكان تعلّم، لا مكان قياس

> **مبدأ**: القياس الحقيقي يبدأ بعد انتهاء التعلّم، في أنظمة الاختبارات والمراجعات. أما داخل الدرس فكل سؤال هدفه الوحيد مساعدة الطالب على الفهم، لا إصدار حكم عليه.

- التقييمات **داخل** الدرس تُعرض بوصفها «تحقق من الفهم» وترافقها تغذية فورية لطيفة.
- **لا يُحفظ** أي تفاعل داخلي (إجابات، محاولات، أخطاء، قراءة تفسير، إعادة) — هذا جزء من عملية التعلم، لا بيانات تحليلية.
- **يُحفظ فقط** اللحظات الفارقة (Milestones): بدأ الدرس، أنهى الدرس، أكمل الوحدة، اجتاز اختبارًا...

### 1.3 عزل الدرس (المبدأ الأهم)

- الدرس لا يعرف عن: الإنجازات، المهام، الاختبارات، المراجعات، لوحة القيادة.
- الدرس (المحرك) يصدر **أحداثًا** (Events) عند اللحظات الفارقة فقط: بدأ، أنهى، اجتاز تقييمًا...
- بقية الأنظمة **تستمع** للأحداث وتبني على أساسها دون المساس بالدرس:
  - نظام الإنجازات يمنح وسام «أول درس».
  - نظام المهام يعتبر المهمة اليومية أُنجزت.
  - نظام المراجعة يضيف الدرس إلى جدول المراجعة.
  - نظام التقدم يحدّث نسبة الإنجاز.
  - نظام الاختبارات يفتح اختبار الوحدة إذا اكتملت الدروس المطلوبة.
- النتيجة: أي نظام جديد يُضاف بعد سنة **دون تعديل سطر واحد** في قلب المحرك.

### 1.4 الباك وقاعدة البيانات تبقى كما هي

- تُغيَّر **الواجهة فقط** للطالب: «Formative Assessment» تظهر له باسم «تحقق من الفهم / سؤال سريع / لنرَ إن وصلت الفكرة».
- الباك (`BlockKind`، الجداول، الأسماء التقنية) تبقى **بدون أي تغيير** في هذه المرحلة.

## 2. المراحل السبع

محرك الدرس يتكون من **سبع مراحل** بالترتيب. كل مرحلة لها `kind` (معرّف المحرك) ودور:

| # | المرحلة | `kind` (المحرك) | الغرض |
|---|---------|------------------|-------|
| 1 | مقدمة الدرس | `intro` | اسم الدرس، المدة، عدد الفقرات والأسئلة، ماذا ستتعلم + زر «ابدأ الدرس» |
| 2 | أهداف الدرس | `objectives` | «بعد الانتهاء من هذا الدرس ستكون قادرًا على...» |
| 3 | التحقق القبلي | `pre_assessment` | «لنعرف من أين نبدأ» — تحديد نقطة البداية بلا حكم |
| 4 | التعلم | `learning` | تناوب { فقرة ← تحقق من الفهم } — **القلب** |
| 5 | الملخص | `summary` | «ماذا تعلمنا اليوم؟» بطاقات / خرائط / رسومات |
| 6 | الاختبار النهائي | `final_assessment` | هنا يبدأ القياس الحقيقي |
| 7 | صفحة الإنجاز | `completion` | 🎉 احتفال + توجيه للدرس التالي |

### 2.2 شخصية المرحلة (Stage Personality)

> مرجع كل قرار تصميمي لاحق: لكل مرحلة غرضٌ تعليمي واحد، وشعور مقصود، ورسالة تتردد في ذهن الطالب، وإجراء (CTA) يعكس تلك الشخصية. لا تُبنى أي شاشة قبل الاصطفاء مع هذا الجدول.

| المرحلة | الهدف | شعور الطالب | الرسالة | CTA |
|---------|-------|-------------|---------|-----|
| Intro | التهيئة | الأمان | «ستتعلم خطوة بخطوة» | ابدأ الرحلة |
| Objectives | الالتزام | الوضوح | «هذه هي وجهتك» | أنا مستعد |
| Pre Check | معرفة نقطة البداية | الاطمئنان | «لا توجد درجات هنا» | ابدأ |
| Learning | التعليم | التركيز | «تعلّم ثم تحقّق» | التالي |
| Summary | الترسيخ | الثقة | «هذا ما تعلمته» | اذهب للاختبار |
| Final | القياس | التحدي | «أظهِر ما تعلمته» | ابدأ الاختبار |
| Completion | الاحتفال | الإنجاز | «أحسنت» | العودة للمقرر |

### 2.1 تدفق المحرك الكامل

```
Not Started
   ↓
Intro
   ↓
Objectives
   ↓
Pre Check
   ↓
فقرة 1 ──→ تحقق من الفهم ──→ (صحيح) فقرة 2 ──→ تحقق من الفهم ──→ ...
                │
                └── (خطأ) إعادة/مراجعة ثم إعادة المحاولة
   ↓
Summary
   ↓
Final Assessment
   ↓
Completion ← Lesson Completed
```

## 3. الهيكل المعماري للمحرك

### 3.1 المراحل تأتي من المحرك، لا من الواجهة

- لا تعرف الواجهة ترتيب المراحل بثبات داخل الكود؛ بل **تستلمها** من المحرك كقائمة `kind`:

```json
[
  { "kind": "intro" },
  { "kind": "objectives" },
  { "kind": "pre_assessment" },
  { "kind": "paragraph" },
  { "kind": "understanding_check" },
  { "kind": "paragraph" },
  { "kind": "understanding_check" },
  { "kind": "summary" },
  { "kind": "final_assessment" },
  { "kind": "completion" }
]
```

### 3.2 سجل الربط (Registry) — من المرحلة إلى المكوّن

```
intro              → IntroStage
objectives         → ObjectivesStage
pre_assessment     → PreAssessmentStage
paragraph          → ParagraphStage
understanding_check → UnderstandingCheckStage
summary            → SummaryStage
final_assessment   → FinalAssessmentStage
completion         → CompletionStage
```

> إضافة مرحلة جديدة (نشاط، مختبر، محادثة ذكية...) = إضافة `kind` + ربطها بمكوّن، **دون** إعادة كتابة المحرك.

### 3.3 واجهة التحكم (Controller API)

- كل المكونات تتعامل مع واجهة واحدة، ولا تعرف المنطق الداخلي:
  - `engine.start()` — بدء الرحلة.
  - `engine.goTo(stage)` — الانتقال لمرحلة (بفحص البوابة).
  - `engine.next()` — الانتقال التالي الشرعي.
  - `engine.completeStage(stage)` — الإعلان عن اكتمال مرحلة.
  - `engine.getState()` — حالة الدرس والمرحلة الحالية.
  - `engine.subscribe(handler)` — الاشتراك في أحداث المحرك.

## 4. مرحلة التعلم — قلب المحرك

> أهم مرحلة؛ تمنع تراكم الفجوات المعرفية: لا ينتقل الطالب لفقرة جديدة وهو يحمل سوء فهم.

### 4.1 التعاقب

```
فقرة (Paragraph) → تحقق من الفهم (Understanding Check) → فقرة → تحقق → فقرة → تحقق → ...
```

### 4.2 شاشة الفقرة

عنصر أساسي واحد في كل مرة، بدون ضوضاء:

```
عنوان الفقرة
──────────────
الصورة
──────────────
الشرح
──────────────
مثال (اختياري)
──────────────
معلومة (اختياري)
──────────────
فيديو (اختياري)
──────────────
[التالي]
```

- زر [التالي] لا ينتقل للفقرة التالية فورًا، بل إلى **تحقق من الفهم**.

### 4.3 «تحقق من الفهم» — سؤال سريع تعليمي

- أداة شرح لا امتحان؛ الغرض معرفة هل وصلت الفكرة.
- يعمل **فورًا** على الشاشة **بلا اتصال بقاعدة البيانات** ولا تتبع للنتيجة.

**السلوك الدقيق:**

```
سؤال تعليمي سريع (اختيار من متعدد / صواب وخطأ / سحب وإفلات /
ترتيب / أكمل الفراغ / اضغط الكلمة الصحيحة ...)
   │
   ├─ إجابة صحيحة →
   │     ✅ أحسنت، فهمت.
   │     نص توضيحي قصير يعلّل لماذا هذا هو الصواب.
   │     [التالي]  ← ينتقل
   │
   └─ إجابة خاطئة →
         لا بأس، لنراجعها سريعًا.
         الصواب هو «...» لأن [الشرح الصحيح].
         [أعِد المحاولة]  ← يعيد الفقرة/السؤال (بلا حد محبط؛ الهدف الفهم)
```

- زر «أعد المحاولة» يسمح بإعادة عرض الفقرة ثم إعادة التحقق (كما في رؤية الرحلة `docs/Student-Learning-Journey-Reference.md:5.5` زر «مراجعة الفقرة»).

### 4.4 لا يغادر التفاعل المحلي إطلاقًا

- لا يُسجَّل اختيار خاطئ، ولا إعادة محاولة، ولا قراءة تفسير، ولا درجة، ولا إحصائية.

## 5. نوعا التقييم: تعليمي وقياسي

> لا نخلط بين نوعين مختلفين تمامًا.

### 5.1 تعليمي (Learning Check) — داخل الدرس

| البحث | القيمة |
|-------|--------|
| الهدف | مساعدة الطالب أثناء التعلّم فقرة بعد فقرة |
| أسماؤه للعرض | «تحقق من الفهم»، «سؤال سريع»، «لنرَ إن وصلت الفكرة» |
| يُقاس؟ | لا |
| يُسجّل؟ | لا |
| يدخل في الإحصائيات؟ | لا |
| يدخل في الدرجات؟ | لا |
| الصورة | معلّم واقف بجانب الطالب: «هل فهمت؟» |
| النهاية | فهم وتحسّن، دون أي سجل |

### 5.2 قياسي (Measurement) — الاختبارات والنهائي

| البحث | القيمة |
|-------|--------|
| الهدف | قياس نتائج حقيقية |
| الأنواع | اختبار الوحدة، الشهر، الترم، المراجعة، **الاختبار النهائي للدرس** |
| يُسجّل؟ | نعم (درجة، وقت، محاولات، نسبة إتقان، نقاط ضعف) |
| يدخل في الإحصائيات والدرجات؟ | نعم |
| متى نتعامل مع قاعدة البيانات؟ | عند اكتمال الاختبار عبر حدث فارق (Milestone) |

### 5.3 الاسم في الواجهة فقط

- الباك وقاعدة البيانات تحتفظان بـ `FormativeAssessment` و`BlockKind` كما هما.
- في واجهة الطالب فقط يظهر الاسم التعليمي «تحقق من الفهم / سؤال سريع».

## 6. دورة حياة الدرس وبوابات الانتقال

### 6.1 حالات الدرس

| الحالة | الوصف |
|--------|-------|
| `Not Started` | الدرس لم يبدأ بعد |
| `In Progress` | الطالب داخل رحلة الدرس |
| `Blocked` | المرحلة الحالية لا يمكن تجاوزها (شرط غير محقق) |
| `Completed` | انتهى الدرس واجتاز النهائي — أُطلق `LessonCompleted` |

### 6.2 بوابات الانتقال (Gates)

| من | إلى | الشرط |
|----|-----|--------|
| Intro | Objectives | يضغط «ابدأ الدرس» |
| Objectives | Pre Check | يضغط «أنا مستعد» |
| Pre Check | Learning | نهاية التحقق (أيًا كانت النتيجة — لا منع ولا عقاب) |
| فقرة | تحقق من الفهم | زر [التالي] |
| تحقق صحيح | المرحلة/الفقرة التالية | إجابة صحيحة فقط |
| تحقق خاطئ | إعادة (نفس الفقرة/السؤال) | إجابة خاطئة → توضيح ثم [أعد المحاولة] |
| آخر تحقق ناجح | Summary | إتمام آخر تحقق |
| Summary | Final Assessment | زر المتابعة |
| Final Assessment | Completion | اجتياز الاختبار النهائي (بعتبة النجاح القياسية) |
| Completion | الخروج من الدرس | فتح الدرس التالي + بث `LessonCompleted` |

> لا توجد في هذه المرحلة بوابة حاجزة غير «تحقق من الفهم» و«الاختبار النهائي».

## 7. الأحداث — مخرجات المحرك فقط

الدرس **ينشر أحداثًا**، وبقية الأنظمة تستمع إليها. القائمة الدنيا:

| الحدث | متى | مَن سيستخدمه |
|-------|-----|--------------|
| `LessonStarted` | بدء الدرس (المرحلة 1) | حساب الوقت، آخر موضع، سلسلة الأيام |
| `PreCheckCompleted` | نهاية المرحلة 3 | تحديد نقطة البداية |
| `FinalAssessmentPassed` | نجاح الاختبار النهائي | احتساب الإتقان والتقدم |
| `LessonCompleted` | انتهاء الرحلة بنجاح | فتح الدرس التالي، إضافة مراجعة، فحص الإنجازات |

> **لا** تُبث أحداث للإجابات والمحاولات داخل «تحقق من الفهم» — فهي ليست لحظات فارقة.

## 8. ما يُحفظ وما لا يُحفظ

### 8.1 لا يُحفظ (داخل الدرس)

- استجابات «تحقق من الفهم» (صحيح/خطأ/الاختيار).
- محاولات وإعادة المحاولات.
- قراءة الفقرات، التنقل بين الأقسام، مشاهدة الفيديوهات.
- أي «عتبة» داخلية غير اللحظات الفارقة.

### 8.2 يُحفظ (Milestones فقط)

- بدأ الدرس (`LessonStarted`).
- اكتمل الدرس (`LessonCompleted`).
- اكتملت الوحدة / اجتاز الاختبار النهائي (تُسلَّم للأحداث).

### 8.3 قاعدة الأنظمة المستقبلية

- الأنظمة المستقبلية (اختبارات شهرية/ترم، مراجعات ذكية، إنجازات، مهام) تُبنى على **الأحداث** لا على تفاصيل رحلة الدرس.
- لا يجوز إضافة حفظ داخل الدرس لاحقًا لأغراض تحليلية؛ كل قياس يُنجز في الأنظمة القياسية.

## 9. عقد البيانات (خريطة المرحلة ← البيانات)

| المرحلة | ما يراه الطالب | البيانات المطلوبة من الباك |
|---------|----------------|-----------------------------|
| Intro | اسم الدرس، المدة، عدد الفقرات/الأسئلة، «ماذا ستتعلم» | `Lesson` (`title`, `summary`, العدّادات) |
| Objectives | قائمة «ستكون قادرًا على...» | `learning_objectives[]` (تُضاف لاحقًا؛ حاليًا تُشتق من ملخص الدرس) |
| Pre Check | الأسئلة | `Assessment(type=pre)` |
| Learning | الفقرات + تحقق الفهم + فيديو اختياري | `Paragraph` + `Assessment(type=formative)` + `LessonVideo` |
| Summary | ملخص الدرس وأهم النقاط | `lesson.summary` + نقاط (تُضاف لاحقًا) |
| Final | أسئلة الاختبار النهائي | `Assessment(type=final)` |
| Completion | الاحتفال + المقارنة قبل/بعد + التحسّن + الدرس التالي | نتيجة النهائي + جلسة الدرس (المحفوظة في الأحداث فقط) |

> **المصدر الحقيقي**: تستهلك الواجهة رحلة الدرس من `LessonFlowResource` (الكتل المرتّبة `blocks[]`)، ثم يضيف المحرك المراحل السبع/المنطقية (`intro`, `objectives`, `summary`, `completion`) حولها. الباك لا يتغير.

## 10. خارج نطاق محرك الدرس (يُؤجَّل)

لا تدخل في هذه المرحلة؛ تُنصّ لكنها تُبنى لاحقًا فوق أحداث الدرس:

- **خارطة التعلم** داخل الدرس (المبتدأ، الخبر، أنواع الخبر...) مع تقدم فوري.
- **الإنجازات (Achievements)**: أول درس، أول وحدة، أيام متتالية، 100 سؤال صحيح، أول اختبار...
- **المراجعة الذكية (Review)**: مفاهيم خاطئة ← قائمة مراجعة ← مراجعة يومية (بأسلوب Anki مصغّر).
- **المهام (Missions)**: يومية/أسبوعية/شهرية لتحفيز الاستمرار.
- **الاختبارات (Exams)**: وحدة، شهر، منتصف/نهاية ترم، شامل — ثابتة وعشوائية.
- **لوحة الطالب (Dashboard)**: «صباح الخير، اليوم لديك درس + مراجعتان + اختبار قصير».

> **القاعدة الكبرى**: أي نظام مستقبلي يبدأ بمراقبة أحداث الدرس، بلا تعديل على المحرك.

## 12. المصطلحات التقنية بالعربي

| المصطلح | المعنى |
|---------|--------|
| Lesson Engine | محرك الدرس — المحرك الذي يحكم الرحلة داخل الدرس |
| Stage | المرحلة — واحدة من الحالات السبع للطالب في الدرس |
| State Machine | آلة الحالات — نموذج يحفظ كل حالة وشروط الانتقال بينها |
| Registry | السجل — يربط نوع المرحلة (`kind`) بالمكوّن الذي يعرضها |
| Gate | بوابة الانتقال — الشرط الذي يسمح بالمرور للمرحلة التالية |
| Learning Check | تحقق من الفهم — تقييم تعليمي داخلي لا يُقاس ولا يُسجّل |
| Measurement | قياسي — تقييم يُسجَّل ويُحتسب (الاختبارات والنهائي) |
| Learning Domain | مجال التعلم — ماهية الكيانات في المنصة |
| Event | حدث — لقطة فارقة يصدرها المحرك لتصله بقية الأنظمة |
| Milestone | لحظة فارقة تُحفظ في القاعدة (بدأ/أنهى/اجتاز...) |
