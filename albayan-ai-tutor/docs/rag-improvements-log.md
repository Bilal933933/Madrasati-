## 2) القرارات المعمارية الدائمة

### معادلة IDF (الموحّدة بين الدروس والمقاطع)
- الوزن = `(الإجمالي + 1) / (ث وأثر + 1)`، مع حد أدنى `0.5`.
- محسوبة عبر `computeLessonTokenWeights(lessons, tokens)` ككتالوج الدروس المرشَّحة، مرة واحدة في `buildLayer1`، وممرَّرة إلى `scoreLesson` و`scoreChunk`.

### MINOR_TOKENS
- `{ الفرق، بين }` — توكنز دلالية بدون وزن، بوزن ثابت `0.5` عند ظهورها.
- تُبقى خارج المقام الجوهري في بوابة الكفاية (العداد والمقام).

### بوابة الكفاية (Sufficiency Gate)
- العتبة الافتراضية `0.6`، والحد الأدنى لطول المحتوى `120` حرفًا.
- قابل للتعديل عبر `RAG_SUFFICIENCY_COVERAGE` و`RAG_MIN_CONTENT_CHARS`.
- المصدر: معايرة فعلية موثّقة (جدول أسفله) — ليست قيمة مفروضة.

#### جدول معايرة البوابة (ثابت)
| السؤال | المغطاة/الجوهرية | النسبة | القرار |
|--------|------------------|--------|--------|
| ما المبتدأ؟ | 1/1 | 1.000 | كافٍ — لا L3 |
| ما الفرق بين المبتدأ والخبر؟ | 2/2 | 1.000 | كافٍ — لا L3 |
| ما علامة رفع المبتدأ؟ | 3/3 | 1.000 | كافٍ — لا L3 |
| ما الخبر وأنواعه؟ | 1/2 | 0.500 | غير كافٍ — تُبنى L3 |
| ما أقسام الكلام في اللغة العربية؟ | 3/5 | 0.600 | كافٍ بالضبط — لا L3 |
| ما سرعة الضوء وكم تبعد الشمس عنا؟ | 0/6 | 0.000 | غير كافٍ — لا تمر البوابة |

الفصل بلا تداخل: أدنى «كافٍ» = 0.600، أعلى «غير كافٍ» = 0.500.

### الكسب الهامشي (Marginal Gain)
- يُضم مقطع/قسم فقط لو أضاف توكنز جوهرية للسؤال غير ممثَّلة بعد في النافذة الحالية (يمنع تكرار الدروس في الممر-gauge).
- يقرأ أول عنصر مهما كان حجمه، ثم يتوقف عند تجاوز الميزانية بعناصر كاملة.

### ترتيب الطبقات L1 → L2 → L3
1. **L1**: مقاطع مطابقة + بوابة كفاية + توازي L1/L2.
2. **L2**: مقاطع `textbook`/`references` (غير عام) ضمن ميزانية الحروف المتبقية + كسب هامشي.
3. **L3**: أقسام الكتب العامة (`references/general`) — **كسولة**: تُقرأ من القرص فقط حين لا تكفي الطبقتان 1 و2 معًا، وضمن الميزانية + كسب هامشي.
- استثناءات الطبقة 3 محتجزة محليًا (`rag.layer3_failed` عبر `logger.warn`)، لا تصل إلى فلتر الأخطاء العام.

### الطبقة الدلالية (pgvector + Hybrid/RRF)
- **قاعدة المتجهات**: قاعدة Neon مستقلة (`VECTOR_DATABASE_URL`) يملكها ai-tutor؛ جدول `knowledge_chunks` بنمط `halfvec(768)` عبر `vector-schema/vector.prisma` (كل عمليات المتجه SQL خام لأن Prisma لا يدعم نصف المتجهات)، وفهرس `hnsw (embedding halfvec_cosine_ops)`.
- **النموذج**: `gemini-embedding-001` بأبعاد 768 عبر MRL (`outputDimensionality`) — بلا `taskType` (خاص Vertex فقط).
- **المصادر المفهرسة**: مقاطع markdown بـ 500 كلمة، أقسام الكتب العامة، وفقرات دروس DB — بمفاتيح `docKey` مستقرة (sha256 من موقع المقطع لا محتواه) وupsert على `doc_key`.
- **الدمج**: الطبقة الدلالية **كسولة** — تُبنى فقط عند عدم كفاية الطبقات 1-3 لبوابة الكفاية (توفير تكلفة الـ embedding لكل سؤال)، ثم تُرتَّب نتائجها عبر **RRF** (دمج رتبة التشابه الدلالي + الوزن المعجمي) مع الكسب الهامشي والميزانية نفسَيهما للطبقات الباقية.
- **الانهيار السعيد**: غياب أو فشل التضمين/قاعدة المتجهات لا يفشل الطلب (`rag.semantic_failed` عبر `logger.warn`) — يُكمَل المعجمي كما كان.
- **بيئة التشغيل**: `EMBEDDING_MODEL`/`EMBEDDING_DIMENSIONS`/`EMBEDDING_BATCH_SIZE`/`VECTOR_TOP_K` (افتراضي 20)/`RRF_K` (افتراضي 60). الفهرسة عبر `npm run index:vector` (مبنية) أو `node dist/cli/indexer.js`.
- **القيود والتباطؤ**: حصة free tier لنموذج `gemini-embedding-1.0` هي `embed_content_free_tier_requests` **1000 طلب/يوم** لكل مشروع/نموذج، تُعاد منتصف ليل Pacific. لتوزيع الطلبات على نافذة الدقيقة (تفادي TPM/RPM اللحظية) تُشغَّل الفهرسة بـ `EMBEDDING_BATCH_SIZE=1` و`INDEXER_DELAY_MS=2500` (راحة بين الدفعات في `indexer.service.ts`). الـ upsert على `docKey` يجعل الاستئناف بعد استنفاد الحصة آمنًا بلا تكرار.
- **`--prefix` على Windows**: `indexer.service.ts` يطبّع المسارات (`\`→`/`) قبل `startsWith` حتى يعمل `--prefix textbook/prep/prep_3` على Windows.
- **حالة الفهرسة (2026-08-18)**: **الفهرسة الكاملة مكتملة — 1815 مقطعًا** (765 كتب عامة + 473 دروس DB + 322 المدرسي + 255 المراجع). `textbook/prep/prep_3` = 321/321. الاستئناف سريع عبر `existingDocKeys()` الذي يتخطّى المقاطع المفهرسة قبل التضمين (يوفّر حصة الـ embedding؛ الجولة النهائية ضمّنت 20 فقط). انقطاعات شبكة عابرة (fetch failed / Connection terminated) غير ضارة — الاستئناف يتقدم بتراكم.
- **معايرة مؤجلة**: العتبات الفعلية (topK، حجم المقطع، نسب الدمج) لم تُعيَر بعد — تُعالج عند الاختبار الحي.

## 3) قاعدة قرارات الحذف — ملزمة
أي حذف لمحتوى موجود (حتى `untracked`) يمر ببروتوكول إلزامي:
1. **توقف** فورًا عن التنفيذ.
2. **عرض الدليل** كاملًا (مقارنات/تجزئات/سياق).
3. طرح **خيارات غير موجَّهة** (بلا خيار «موصى به» في المقدمة).
4. **انتظار اختيار صريح** من القائد.
5. **تسجيل النص الحرفي** للاختيار في التقرير — التوثيق الحرفي هو الفيصل بين «قرار موثَّق» و«استنتاج الوكيل».

## 4) البند المؤجل — حمل الإقلاع المتزامن

- **الوصف**: `onModuleInit` يحمّل `docs` + `generalBooks` بشكل متزامن قبل جاهزية الخدمة.
- **معيار إعادة النظر الصريح** (لا يُفتح دونه):
  - نمو فعلي في `textbook/` أو `references/primary` يرفع حمل الإقلاع عن ~4KB الحالية، **و**
  - قياس زمن `onModuleInit` الفعلي يُبرر التغيير.
- القياس الحالي: `textbook/primary` = ملف واحد 2.4KB، `references/primary` = ملف واحد 1.6KB، `references/general` = 5 كتب (كسولة، metadata فقط عند الإقلاع).
